# HW2：可审核的信息工程习题解答系统

## 问题定义

场景是学生学习信息工程课程时，需要数值正确、单位一致且证据可追溯的解答。
系统结合教材检索、九个确定性工具、MCP 和展示界面，通过 Solver/Reviewer 协作完成解答与审核。
实现包含受控审核循环、明确失败终态、运行产物保存、同题设计对比及自动测试。

## 角色、协作与 harness

工具及检索是共享证据准备层，不被冒充成独立 LLM Agent。
Solver Agent 使用题目、教材片段、确定性工具输出及选定 Skill 生成草稿。
Reviewer Agent 接收独立审核系统提示和完整证据，检查任务满足情况、数值、单位、引用及推导，
仅返回包含 `approved`、`summary`、`issues` 的 JSON。
两者可使用同一个 MiniMax-M2.7，但角色提示、输入契约和输出职责不同。

```text
题目 → 路由/规划 → 教材检索及真实 MCP 工具 → 固定证据上下文
                                              ↓
                    Solver 草稿 → Reviewer → 本地硬审核门
                        ↑                         │
                        └── 驳回反馈 ─────────────┤
                                         通过：结束
                                  达到轮数/错误：失败
```

Harness 默认最多三轮，可配置一至五轮。每轮最多调用 Solver 和 Reviewer 各一次。
通过则停止；驳回则把上一轮草稿及审核意见加入下一轮 Solver 的输入。
工具只在准备阶段执行，不在每轮无谓重复调用。模型请求设置超时且禁用 SDK 自动重试。
流程日志包括审核角色、硬审核门及停止原因，因此可以区分模型批准与最终验收。

审核 JSON 使用严格类型，字符串 `"true"` 不能代替布尔值；通过与非空问题列表不允许同时出现。
本地门检查引用编号是否存在，提供教材时是否使用引用，结构化计算结果是否与真实工具一致。
即使 Reviewer 错误批准，本地数值/单位门仍能驳回。
它不能验证每一句开放域文字；语义正确性仍受模型能力和教材检索质量限制。

## 停止条件与失败路径

| 情况 | 终态 / 停止原因 |
| --- | --- |
| Reviewer 及硬审核门通过 | passed / review_approved |
| 三轮仍被驳回 | failed / max_rounds_exceeded |
| Solver 异常或空草稿 | failed / solver_error |
| Reviewer 调用失败或审核格式无效 | failed / reviewer_error |
| 确定性工具失败 | failed / tool_error |
| 必需教材证据不可用 | failed / evidence_unavailable |
| 无法保存运行证据 | failed / artifact_write_error |
| 对照组明确关闭审核 | unreviewed / review_disabled |

失败草稿明确标记未验收，不作为通过结果返回。CLI 对失败返回退出码 2。
API 错误、密钥缺失不会自动换成 DeepSeek；仅调用明确选定的账户和服务。

## 可检查证据与运行方式

每次运行保留请求、工具/教材证据、完整逐步 trace、各轮草稿和 verdict、角色消息、最终报告、
模型调用次数、实际返回 token 和耗时。目录为 `runs/<run-id>/`，live 与 simulated 模式分开标记。
配置 key 在产物中脱敏，`.env` 被 Git 忽略，提交样例配置而非真实密钥。

本机使用 MiniMax 国内 OpenAI 兼容接口，模型为 MiniMax-M2.7。
公开仓库的轻量复现选择 TF-IDF 后端，用自编小讲义重建索引，不必加载 Qwen 或使用 GPU。
完整教材、模型和索引仅保存在本地，不随 GitHub 仓库公开。
系统支持可选 Qwen embedding 后端，但本次 MAS 验证不以运行 Qwen 检索为前提。
React Web 显示 timeline、messages、verdicts；自动集成测试检查 Web API 响应及产物。

```bash
ie-agent reproduce                    # 真实工具，模拟模型；无需 key
ie-agent benchmark                    # 真实模型；使用 MiniMax 订阅额度
python scripts/verify_workflow.py --live  # 测试及真实运行，保存 terminal.log
```

屏幕录像需要另外录制；终端文字记录只是辅助证据。

## 测量设计与解释

固定题集包含二元熵、四元熵、欧姆定律、RC 时间常数、卷积和科学计算六题。
题目、工具参数、独立预先定义的 gold、模型相同，仅改变是否启用 Reviewer 和修订循环。
比较：结构化答案正确率、失败率、模型调用次数、输入/输出 token、总延迟及审核轮数。
正确率要求最终数值及约定单位同时匹配；时间、电学量要求 SI 单位，容差为 1e-6。
这是任务输出契约的满足率，不是开放域回答的通用准确率。

2026-10-01 完整六题真实实验：单轮 5/6（83.3%），审核循环 6/6（100%），双方失败率均为 0。
单轮调用 6 次，输入/输出 token 为 2933/2867，平均延迟 7452.5 ms；
审核循环调用 12 次，token 为 7664/5382，平均延迟 16361.9 ms。
证据：[真实六题对比](../artifacts/live-comparison/report.md)。差异主要来自 RC 的 SI 输出契约。
单轮给出 `1 ms`，与 `0.001 s` 数学等价，但未遵循明确要求的 SI 单位，因此本样本不能
证明审核提高了整体数学能力；它展示的是审核与硬规则提高输出契约遵循，并增加 token 和延迟。
另归档早期真实试跑中的[两轮修订案例](../artifacts/runs/20261001T120314-91933fbcde/review.json)：
第一轮出现同类单位问题，被硬审核门驳回，第二轮改为 `0.001 s` 后通过。
36 项自动测试通过，七类成功/失败场景均符合预期退出码；完整验证记录：
见[终端记录](../artifacts/verification/terminal.log)及[验证清单](../artifacts/verification/verification.json)。

经用户明确同意发送少量教材片段后，另完成一次真实“检索→工具→Solver→Reviewer”运行：
检索得到五段教材，答案引用第二段的熵公式，计算结果为 1 bit，审核通过。
该次教材证据仅保存在本地，不发布到 GitHub，避免公开教材片段。
公开仓库另提供[真实工具解答运行](../artifacts/runs/20261001T120005-cee8fc3be8/report.md)，
并提供自编资料用于从新克隆开始的实际检索验证。
该运行使用已有 TF-IDF 索引，模型调用两次，输入/输出 token 为 5783/840。
Qwen embedding 后端尚未在当前环境进行端到端复测，不能将这次结果推广为 Qwen 验证成功。

离线对照刻意注入第一轮错误，使“驳回→修订”可重复验证；离线 token 为 0，
不能将其受控成功率包装为真实模型表现。真实模型输出具有随机性，重复运行结果可能变化。
本项目不按未知订阅规则估算人民币费用，只记录 API 实际返回的 token；额度以控制台为准。
